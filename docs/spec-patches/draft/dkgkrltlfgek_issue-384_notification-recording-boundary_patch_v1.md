# SPEC-384-01: 알림 적재 경계 — 도메인 Commit 보존과 재실행 멱등

`SPEC-382-01`이 알림의 유형·수신자·응답 계약을, `SPEC-383-01`이 저장 불변식을 정합니다.
이 Patch는 그 둘이 정하지 않은 하나, **알림 적재가 원인 도메인 트랜잭션과 맺는 관계**만
정합니다. 트랜잭션 규칙은 이 Patch에만 있고 다른 Patch가 중복 정의하지 않습니다.

`ALERT-002`가 요구하는 방향은 하나입니다 — 도메인 트랜잭션이 실패하면 알림을 확정하지
않습니다. 그 역방향, 즉 알림 실패가 도메인까지 실패시키는 원자성은 요구하지 않습니다.

## 추가 사항

### 알림은 도메인 Commit을 되돌리지 않는다

- **알림은 이미 확정된 사실을 알리기만 합니다.** 어떤 도메인 상태, 자금 이동, 잔액도 바꾸지
  않고 도메인 처리의 성공 여부를 결정하지도 않습니다.
- 알림 적재는 **원인 도메인 트랜잭션이 Commit된 뒤에** 별도 트랜잭션으로 수행합니다.
- 알림 적재가 어떤 이유로 실패하더라도 이미 Commit된 예치·정산·환불·근무 확정은 그대로
  유지됩니다. 알림 실패는 도메인 응답을 실패로 바꾸지 않습니다.
- 알림 적재는 외부 시스템 호출을 하지 않습니다.

`P1` 알림의 제약 위반, 데이터 길이, Mapper·배포 불일치가 `P0` 자금 처리를 중단시키는 경로를
만들지 않기 위해서입니다. 알림 Endpoint 전체가 죽어도 예치와 정산은 계속 동작해야 합니다.

### 실패한 알림은 유실되며, 그 한계를 계약으로 명시한다

이 MVP는 내구성 있는 Outbox나 자동 재시도를 두지 않습니다. 따라서 위 선택의 대가는
**알림 유실**이며, 이를 숨기지 않고 다음과 같이 다룹니다.

- 알림 적재 실패는 `WARN` 이상으로 기록하며, 기록에는 `traceId`, `notiType`, `sourceType`,
  `sourceId`, 수신자 식별자를 남겨 어떤 이벤트의 알림이 빠졌는지 사후에 특정할 수 있게
  합니다.
- 기록에 알림 본문(`title`, `content`)과 개인 식별 정보는 남기지 않습니다.
- 복구는 운영자가 위 기록으로 대상을 특정해 같은 이벤트를 다시 적재하는 방식입니다. 재적재는
  `SPEC-383-01`의 유일 제약 덕분에 안전하게 여러 번 시도할 수 있습니다.
- **한계**: 자동 복구가 없으므로 운영자가 기록을 확인하지 않으면 알림은 그대로 누락된
  상태로 남습니다. 자동 재시도가 필요하다고 판단되면 별도 이슈와 Patch로 Outbox를 도입해야
  하며, 그때도 이 Patch의 "도메인 Commit을 되돌리지 않는다"는 유지됩니다.

### 재실행 멱등

- 같은 도메인 이벤트가 재시도, Scheduler 재실행, 중복 요청, 운영 재적재로 여러 번 처리돼도
  수신자당 알림은 한 건입니다. 중복 판정은 애플리케이션 선검사가 아니라 `SPEC-383-01`의
  유일 제약으로 합니다.
- 중복 유일 제약 위반은 실패가 아닙니다. "이미 같은 이벤트의 알림이 있다"로 해석하고 성공과
  같게 처리합니다.
- 수신자가 둘인 유형에서 한 수신자의 알림이 이미 있고 다른 수신자의 알림이 없으면, 없는
  쪽만 새로 만듭니다.

### 안읽음 개수

- 안읽음 개수는 0 미만이 될 수 없습니다.
- 이미 읽은 알림을 다시 읽음 처리해도 안읽음 개수가 변하지 않습니다.
- 안읽음 개수는 저장된 읽음 상태에서 계산하며 별도 집계 값을 따로 유지하지 않습니다.

## 완료 조건

- [ ] 알림 적재가 실패해도 예치·정산·환불·근무 확정 Commit이 유지되고 도메인 응답이 성공이다.
- [ ] 알림 Table 접근이 전부 실패하는 상태에서도 자금 처리가 정상 완료된다.
- [ ] 도메인 트랜잭션이 실패하면 알림이 남지 않는다.
- [ ] 알림 적재 실패가 `traceId`·`notiType`·`sourceType`·`sourceId`·수신자와 함께 기록되고,
      기록에 알림 본문과 개인 식별 정보가 없다.
- [ ] 기록으로 특정한 이벤트를 다시 적재하면 알림이 생성되고, 이미 있으면 한 건을 유지한다.
- [ ] 같은 이벤트를 두 번 처리해도 수신자당 알림이 한 건이다.
- [ ] 수신자 둘 중 한쪽 알림만 있는 상태에서 재처리하면 없는 쪽만 생성된다.
- [ ] 이미 읽은 알림을 다시 읽음 처리해도 안읽음 개수가 줄지 않고 음수가 되지 않는다.
- [ ] 안읽음 개수가 저장된 읽음 상태와 항상 일치한다.
