# SPEC-187-01: 비밀번호 변경 뒤 Session 처리와 실패 필드 귀속을 정한다

`AUTH-009`와 `API_SPEC.md`는 `PATCH /api/users/me/password`가 성공하면 `204`를 반환한다고
정하지만, **그 뒤 인증 상태를 어떻게 할지는 정하지 않는다.** `AUTH-011`(비밀번호 재설정)에만
"기존 Session 정책에 따라 인증 상태를 갱신한다"는 문장이 있고, 변경 쪽에는 대응하는 문장이
없다. 실패 응답이 어떤 필드를 지목하는지도 정해져 있지 않다.

이 Patch는 그 두 공백만 채운다. 비밀번호 경계(8~64자, UTF-8 72byte 이하, 절단 없음),
BCrypt 단방향 저장, 인증 Principal만 사용하는 규칙은 이미 정식 SPEC이 정한 그대로이며
여기서 다시 정하지 않는다.

## 추가 사항

### 변경에 성공하면 로그인 상태를 유지한 채 Session을 새 것으로 바꾼다

- 사용자는 비밀번호를 바꾼 직후에도 로그인 상태로 남는다. 다시 로그인하라고 요구하지
  않으며, 변경 화면에서 하던 흐름을 그대로 이어간다.
- 변경 이전의 Session 식별자는 더 이상 사용할 수 없다. 자격 증명이 바뀌었으므로 바뀌기
  전에 발급된 식별자를 그대로 재사용하지 않는다.
- 변경에 실패하면 Session은 아무것도 달라지지 않는다.

### 현재 비밀번호가 틀리면 그 사실을 `currentPassword` 필드에 귀속시킨다

- 응답은 `400 VALIDATION_ERROR`이고, `fieldErrors`에 `currentPassword` 항목 하나를 담는다.
- 새 비밀번호가 경계를 벗어난 경우는 `newPassword`에 귀속시킨다. 두 실패를 같은 필드로
  묶지 않는다 — 화면은 이 필드명으로 어느 입력칸에 오류를 표시할지 정한다.
- `fieldErrors`의 사유 문구는 화면이 사용자에게 그대로 보여주는 문장이다. 내부 코드값을
  넣지 않는다.
- 어떤 실패 응답에도 비밀번호 원문, Hash, Session 식별자를 담지 않는다.

### 활성 계정만 비밀번호를 바꾼다

- 로그인은 인증하는 순간에만 계정 상태를 확인한다. Session이 살아 있는 동안 계정이
  잠기거나 탈퇴 처리되면 그 Session으로 비밀번호를 계속 바꿀 수 있다.
- 변경 시점에 계정 상태를 다시 확인하고, `ACTIVE`가 아니면 `403 FORBIDDEN`으로 거부한다.

## 완료 조건

- [ ] 비밀번호를 바꾼 뒤 다시 로그인하지 않고도 보호 화면을 계속 사용할 수 있다.
- [ ] 변경 전에 쓰던 Session 식별자가 변경 뒤에는 그대로 남아 있지 않다.
- [ ] 변경에 실패하면 Session 식별자가 그대로다.
- [ ] 이전 비밀번호로는 로그인할 수 없고 새 비밀번호로는 로그인된다.
- [ ] 현재 비밀번호를 틀리면 화면의 "현재 비밀번호" 칸에 사유가 표시된다.
- [ ] 새 비밀번호가 8자 미만·64자 초과·UTF-8 72byte 초과이면 거부되고, 72byte 값은
      절단 없이 그대로 통과한다.
- [ ] 계정이 `ACTIVE`가 아니면 살아 있는 Session으로도 비밀번호를 바꿀 수 없다.
- [ ] 응답, 오류, 일반 로그 어디에도 비밀번호 원문과 Hash가 나타나지 않는다.
