# SPEC-359-01: 근로계약서 PDF 서버 내장 양식 Template

## 추가 사항

`DEC-DOCUMENT-STORAGE`가 정한 "서버 내장 Template"의 표현 형식을 좌표 기반 텍스트 나열에서
HTML/CSS 문서 양식으로 확정한다. 저장 Key, MIME, Checksum, Version 규칙, 자동 생성 Aggregate
경계는 그대로 둔다.

- 계약 PDF는 서버에 내장한 단일 HTML/CSS Template으로 렌더링하며, "단시간·일용 근로계약서"
  제목 아래 계약 당사자, 근로계약 기간 및 장소, 근로시간 및 휴게시간, 임금 네 Section과 법정
  고지 문단, 체결 문구, 서명란 순서로 구성한다.
- 계약 당사자 Section은 사업주(사업장명·대표자)와 근로자(이름)를 표시한다. 각 당사자의
  연락처는 `users.phone`이 있을 때만 이름 뒤에 괄호로 붙이고, 없으면 그 표시를 통째로 뺀다.
  연락처는 계약 확정 시점에 굳히지 않고 열람·생성 시점 값을 그대로 읽는다.
- 근로계약 기간 및 장소 Section은 근로일자(근무일 하루로 한정, 재계약 미약정), 근무장소
  (사업장명과 주소), 담당업무를 표시한다.
- 근로시간 및 휴게시간 Section은 시작·종료 시각과 총 근로시간, 휴게 시간과 유급 여부를
  표시한다.
- 임금 Section은 일급과 지급 방법을 표시한다.
- 서명란은 사업주와 근로자 두 칸으로 나누고 각 칸은 역할, 성명, 일시를 같은 형식으로 표시한다.
  - 사업주 칸: 성명과 `근무등록 일시`(`work_cases.created_at`). 사업주는 별도 서명 절차 없이
    근무 조건을 등록한 시점을 계약 제시 시점으로 본다.
  - 근로자 칸: 성명과 `서명 일시`(`document_signatures.signed_at`).
  ORIGINAL은 근로자 칸의 성명과 일시를 서명 전 상태로 표시하고, SIGNED는 근로자가 직접 입력한
  이름과 서명 일시를 표시한다. ORIGINAL과 SIGNED의 차이는 이 근로자 칸 내용뿐이다.
- 근로기준법 제17조가 요구하는 법정 고지 사항을 한 문단으로 명시한다. 이 서비스의 계약이
  일용근로소득으로 과세되는 하루짜리 근로계약임(`DASH-003`)을 전제로, 연차유급휴가·주휴수당은
  발생 요건(계속근로기간)을 충족하지 않음을 밝히고, 산재·고용보험은 원칙 적용, 국민연금·건강보험은
  1개월 미만 근로로 적용 제외될 수 있음을 밝히고, 임금이 최저임금법 등 관계 법령을 준수해야
  함을 밝히고, 근로계약서 교부 사실을 밝힌다. 서버는 개별 근무의 최저임금 준수 여부를 검증하지
  않으므로, 임금 문구는 준수 사실을 단정하지 않고 준수 의무만 밝힌다.
- 계약서 내용은 이미지가 아닌 텍스트로 렌더링해 열람 도구에서 검색·복사할 수 있어야 한다.
- Snapshot 값에 Markup 문자가 들어와도 양식이 깨지지 않고 입력한 문자 그대로 표시한다.
- 문서 생성·수정 시각은 렌더링 시각이 아니라 계약 수락 시각으로 고정한다.
- 근로자 주소와 생년월일은 이 Patch 범위에 포함하지 않는다. 주소는 `users`에 컬럼이 없어
  별도 Migration 승인이 선행돼야 하고, 생년월일은 근로기준법 일반 기재사항이 아니며 연소근로자
  판별 목적으로만 의미가 있어 회원가입 연령 정책이 먼저 결정돼야 한다. 사업자등록번호는 근로
  기준법 §17과 참고한 표준 서식 어디에도 없어 이번 양식에 포함하지 않는다.

## 완료 조건

- [ ] 계약 PDF에 제목, 사업장명과 주소, 근로 시간, 휴게 시간과 유급 여부, 합의 일급, 사업주·근로자
      이름, 이용약관 판번호, 수락 일시가 모두 텍스트로 추출된다.
- [ ] SIGNED PDF에서만 근로자 서명 이름과 서명 일시가 추출되고 ORIGINAL에는 나타나지 않는다.
- [ ] 사업주 칸에 근무등록 일시가 표시되며 계약 수락 일시와 구분된다.
- [ ] 근로계약 기간 및 장소 Section에서 근로계약기간이 근무일 하루로 명시된다.
- [ ] 연차유급휴가, 주휴수당, 사회보험 적용, 최저임금, 근로계약서 교부 고지가 모두 텍스트로
      추출된다.
- [ ] 사업주·근로자 연락처가 있으면 이름 뒤에 표시되고, 없으면 그 표시가 나타나지 않는다.
- [ ] 사업장 주소나 업무 내용이 길어도 값이 잘리거나 렌더링이 실패하지 않는다.
- [ ] 업무 내용에 `<`, `&` 같은 문자가 포함되어도 입력한 문자열 그대로 표시된다.
- [ ] 문서 정보의 생성·수정 시각이 계약 수락 시각과 같다.
- [ ] 계약 자동 생성과 당사자 열람 경로가 기존과 같은 Key·MIME·Checksum으로 동작한다.
