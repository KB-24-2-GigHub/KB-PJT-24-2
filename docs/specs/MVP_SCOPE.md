- 목적: **무엇을 어떤 순서로 시연하고, 각 단계의 성공을 어떻게 눈으로 판정하는지**를 확정한다.
- 이 문서는 요구사항 ID·API 매핑을 포함하지 않는다. 매핑·P0 재분류·명세 반영은 후속 작업에서 수행한다.

## 0. 시연 전제

| 항목 | 내용 |
| --- | --- |
| 등장 인물 | 사장님(냠냠과자점), 알바생 A(정상 출근), 알바생 B(지각), 알바생 C(노쇼) |
| 계정 상태 | 4명 모두 회원가입 완료. 사장님은 사업장 미등록(첫 로그인) 상태 |
| 자금 상태 | 사장님 전자지갑 잔액 0원에서 시작 |
| 시연 기기 | 사장님 화면 1대 + 알바생 화면 1대(또는 A/B/C 계정 전환), QR 스캔 가능한 카메라 |
| 시간 제어 | 근무 시작/종료, 노쇼 판정(`min(시작+1시간, 종료)`), 3년 경과 보존 만료는 실제 시간을 기다리지 않고 시연용으로 앞당길 수 있어야 함 |
| 필수 여부 표기 | **P0** = 없으면 시연 자체가 끊김 / **P1** = 시연 설득력에 기여, 대체 설명 가능 / **P2** = 생략 가능 |

**구간 성공 기준:** 정상 근무는 약정 일급 전액 지급, 지각·조퇴 근무는 저장된 근태 비례 Snapshot에 따른 WORKER 지급과 OWNER 차액 환불, 노쇼 근무는 OWNER 전액 환불로 정확히 소진되고, 모든 건에서 `WORKER 지급액 + OWNER 환불액 = 최초 예치액`이 성립한다. **이 정합성이 시연의 핵심 클라이맥스다.**

## 7. 시연 판정 요약

시연이 "성공"이려면 다음 5개가 화면으로 증명되어야 한다.

1. **온보딩 → 사업장 → 충전**까지 끊김 없이 진행된다. (1-2 ~ 1-6)
2. **근무 등록 → 초대 링크 → 수락 → 계약서 자동 생성 + 예치**가 한 흐름으로 이어진다. (2-2 ~ 3-6, 4-5)
3. **QR 출퇴근**이 실제 스캔으로 상태를 바꾼다. (5A-2, 5A-4)
4. **정상 / 지각 / 노쇼 세 가지 결말**에서 정상은 약정 일급 전액 지급, 지각은 비례 지급·차액 환불, 노쇼는 전액 환불로 처리되고 합계가 최초 예치액과 일치한다. (5A-6, 5B-6, 5C-3)
5. **양쪽(사장님·알바생) 화면에서 같은 사실이 같게 보인다.** (상태·금액·문서)
