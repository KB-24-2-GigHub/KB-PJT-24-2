# 요구사항 정의서

| 항목        | 값              |
| ----------- | --------------- |
| 명세 릴리스 | `9.0.0`         |
| 승인일      | 2026-08-21      |
| 소유자      | PM/Admin Master |

이 문서는 Gig Hub가 제공해야 하는 제품 기능과 수용 기준을 정의합니다. HTTP 계약은
[API_SPEC.md](API_SPEC.md), 미결 정책은 [DECISIONS.md](DECISIONS.md), 요구사항별 연결은
[SPEC_TRACEABILITY.md](SPEC_TRACEABILITY.md)를 따릅니다.

## 읽는 법

- 요구사항 ID는 기획, API, 도메인, 테스트를 연결하는 안정적인 식별자입니다.
- 우선순위는 `P0`(핵심 시연 필수), `P1`(보조 시연), `Deferred`(후속 제품 범위)입니다.
- 수용 기준은 기능의 완료 조건입니다. 화면이나 저장 구조의 존재만으로 충족되지 않습니다.
- Open 결정이 연결된 항목은 승인된 범위까지만 계약이며, 미결 부분을 임의로 보완하지
  않습니다.

## MVP P0 시연 계약

이 섹션은 2026-08-10에 PM/Admin이 제공한 원본 [MVP_SCOPE.md](MVP_SCOPE.md)의 시나리오 A를
안정적인 요구사항 ID·API·결정·이슈와 연결한 규범 계약입니다. 제품 범위, Priority 또는 화면
성공 결과가 충돌하면 원본이 우선하며, 이 문서는 원본에 없는 매핑과 공식 수용 계약을
제공합니다. 목표 계약의 존재와 현재 구현 완료 판정은 별개입니다.

시연의 당사자는 냠냠과자점 OWNER와 정상 출근 A, 30분 지각 B, 노쇼 C WORKER입니다. 네
계정은 가입된 합성 계정이고 OWNER는 사업장 0개, 지갑 가용 잔액 0원에서 시작합니다. 시작·종료,
노쇼 판정과 보존 만료는 공유 데이터가 아닌 로컬·폐기 가능한 시연 환경의 제어 Clock으로
앞당길 수 있어야 합니다.

계약·구현 상태를 관리합니다.

### 장기 Work 생명주기

근무 생성, 초대 발급, 수락과 계약 확정은 서로 다른 HTTP 요청입니다. `DRAFT`와 `PENDING`은
수분 또는 수시간 지속할 수 있는 정상 영속 상태이며 각 요청은 필요한 짧은 Transaction을
끝내고 서버 Thread·Connection·Lock을 반환합니다. 브라우저 종료, 새로고침, 로그아웃과 재로그인
뒤에도 DB 상태와 다시 연 초대 Link로 흐름을 계속합니다. 수락 요청은 초대 상태·만료·조건
Version, Work Case 당사자·상태, OWNER 가용 자금을 잠금 아래 다시 검증하고 다중 모듈 확정만
하나의 짧은 원자 Transaction으로 Commit합니다.

## 공통 제품 원칙

- 가입과 로그인은 `OWNER`, `WORKER` 역할 흐름을 구분합니다.
- 인증은 Spring Security 기반 HttpSession을 사용하며 역할과 리소스 소유권, CSRF를 서버가
  검증합니다.
- 입력은 승인된 정규화 후 검증합니다. 전화번호는 공백·하이픈을 제거한 숫자 문자열로
  저장·반환하고 비밀번호 원문은 trim하거나 대소문자를 바꾸지 않습니다.
- 전화번호는 서로 독립된 `users.phone`, `workplaces.phone`에만 정규화된 평문으로 저장하고
  요청·응답·SQL 바인딩 로그에 남기지 않습니다. 실제 개인정보 투입, 외부 공개 배포,
  검색·중복 검사 전에는 인증된 암호화를 재검토합니다.
- 일반 성공은 `{data: ...}`, 목록은 `{data: {content, page}}`, 오류는
  `{code, message, traceId, fieldErrors?}` 형식을 사용합니다.
- 목록은 `page=0`, `size=20`, 최대 `size=100`을 공통 기준으로 사용합니다.
- API에서 실제 발생 시점은 UTC `Instant`, 날짜 자체는 `LocalDate`로 표현합니다. 사용자가
  분리 입력한 날짜와 시간은 서버가 `Asia/Seoul` 기준으로 결합합니다.
- DB `DATETIME(6)`에는 `Asia/Seoul` 지역 시각을 저장하고 API 경계에서 UTC로 변환합니다.
- 금액은 음수가 아닌 KRW 원 단위 정수입니다.
- 충전, 출금, 초대 수락, 정산 승인은 멱등성과 원자성을 보장합니다.
- 충전 요청의 PIN은 Mock 계좌 인증에만 사용합니다. 실행 시 인증 기준은 Mock 계좌에만 두고
  주문·원장·멱등 Fingerprint와 응답 Snapshot·응답·예외 메시지·오류·감사·SQL 바인딩을
  포함한 모든 로그에는 PIN 원문이나 파생값을 저장하지 않습니다.
